02

前端与多端

采购门户、移动商城、管理工作台与助手界面面向不同业务场景，提供相应的交互入口。各前端工程依据业务需求与终端特性选用技术框架，并通过组件复用与统一工程规范，支持功能扩展与持续维护。

采购门户

Nuxt 4 · Vue 3

面向企业采购场景，提供商品展示与采购操作的网页入口，通过页面渲染与组件化开发，支持前台页面的构建与持续迭代。

  • 页面渲染：结合页面需求组织内容生成与加载。
  • 静态化交付：将适合静态化的页面预先生成，便于托管与分发。
  • 样式复用：通过原子化样式组织界面，支持页面样式的一致性与维护。

移动多端商城

uni-app 3 · Vite 5

面向移动购物场景，通过跨端工程复用通用页面与业务逻辑，并适配不同终端的布局、交互与平台能力。

  • 跨端复用：以共享代码组织通用功能，减少各终端的重复开发。
  • 终端适配：针对 H5、小程序与移动应用处理界面及平台接口差异。
  • 分包加载：按功能拆分应用资源，支持按需加载。

管理工作台

Vue 3 · Element Plus

面向日常业务管理，通过表格、表单与筛选组件组织复杂操作，并结合界面配置与多语言支持，满足不同管理场景的使用需求。

  • 表格配置：保存用户的列展示配置，便于持续使用。
  • 多语言支持：提供中英文界面，统一管理界面文本。
  • 依赖分包：将大型依赖独立拆分，优化资源加载组织。

助手界面

Next.js · React 19

面向对话式交互，整合消息展示、结构化结果与语音交互，为用户提供获取信息和发起操作的界面入口。

  • 对话交互：组织消息输入、回复展示与会话状态反馈。
  • 结构化呈现：通过可组合的界面组件展示助手返回的结果。
  • 语音交互：衔接语音输入与输出，支持语音形式的交流。
03

后端微服务

以 Java、Spring Boot 与 Spring Cloud Alibaba 为基础，后端按业务域组织服务，并通过接口契约协作。规则引擎与状态机分别承载业务规则和单据状态流转，使业务处理逻辑具有明确的组织方式。

服务契约

契约模块 · 接口版本管理

通过契约模块定义服务接口与数据结构，为服务之间的调用提供明确约定，便于跨模块协作与接口变更管理。

  • 接口定义：明确服务提供的操作、请求参数与返回结果。
  • 数据约定：统一调用双方交换的数据结构。
  • 版本管理：管理契约变更，协调调用方与提供方的适配。

规则引擎

规则引擎

将促销、定价等业务规则交由规则引擎组织与执行，减少规则逻辑在业务代码中的分散，便于规则维护与调整。

  • 规则组织：集中表达业务条件与处理动作。
  • 规则执行：根据业务输入匹配规则，生成相应处理结果。
  • 规则调整：在引擎支持范围内更新规则，减少对主流程代码的改动。

状态机

订单 · 履约单 · 包裹状态机

通过状态机管理订单、履约单与包裹的状态变化，明确各阶段允许执行的操作与转换条件，使单据流转具有清晰的规则约束。

  • 状态定义：明确不同单据的业务阶段。
  • 转换约束：限定状态之间允许的转换路径与触发条件。
  • 流程衔接：将状态转换与相应业务处理关联，组织单据流转逻辑。
